# Bayesian Fitting Procedures

This document formally specifies the mathematical optimization strategy driving the Maximum A Posteriori (MAP) estimation across the `src/fitting_procedures/` logic. 

Because the Cortico-Cerebellar architecture models dynamic internal states generated by chronological choices across continuous trials, static likelihood mapping is computationally intractable. A customized, highly-optimized C++ sampling paradigm must be deployed.

---

## 1. DDM First-Passage Time Density
**File:** `src/models/shared_utils.h`

### Intuition
To extract probabilities, behavioral reaction times ($RT_t$) and choices ($Ch_t \in \{1, 2\}$) must be jointly modeled. The standard analytical solution utilizes Navarro & Fuss (2009) to estimate the passage time of a Wiener diffusion process hitting an upper or lower boundary.

### Mathematical Formulation
The First-Passage Time density is calculated using the truncated infinite sum for small vs. large elapsed times $t = RT - t_{nd}$:

For $t / a^2 \geq 0.08$ (Large-time approximation):
$$ f(t \mid v, a, w) = \frac{\pi}{a^2} e^{-v a w - \frac{v^2 t}{2}} \sum_{k=1}^{\infty} k \sin(k \pi w) e^{-\frac{k^2 \pi^2 t}{2 a^2}} $$

For $t / a^2 < 0.08$ (Small-time approximation):
$$ f(t \mid v, a, w) = \frac{1}{\sqrt{2 \pi t^3}} e^{-v a w - \frac{v^2 t}{2}} \sum_{k=-\infty}^{\infty} (w + 2k) e^{-\frac{(w + 2k)^2 a^2}{2t}} $$

### Line-By-Line Code Mapping
```cpp
// shared_utils.h (Lines 15-21): Large-Time Summation

    for (int k = 1; k <= 30; ++k) {

        sum += term;
```

## 2. Metropolis-within-Gibbs Sampler
**File:** `src/fitting_procedures/mcmc_sampler.cpp`

### Intuition
Due to the non-convex geometry of the Cerebellar Expansion layer, gradient-descent algorithms (e.g., L-BFGS, Adam) frequently collapse into local minima or suffer exploding gradients during time-series unfolding. We utilize a Metropolis-Hastings (MH) MCMC approach, perturbing dimensions sequentially and comparing the accepted joint log-likelihood.

### Mathematical Formulation
A proposal vector $\phi'$ is generated from a symmetric Gaussian jump distribution centered on the current state $\phi_{p}$:
$$ \phi_{p}' \sim \mathcal{N}(\phi_{p}, \sigma_{jump}^2) $$

The acceptance ratio $\alpha$ is given by the difference in Curvature-Penalized Log-Likelihoods:
$$ \ln \alpha = \ln \mathcal{L}(\phi') - \ln \mathcal{L}(\phi) $$
If $\ln \mathcal{U}(0,1) \leq \ln \alpha$, the proposal is accepted.

### Line-By-Line Code Mapping
```cpp
// mcmc_sampler.cpp (Lines 29-30): Gaussian Jump Proposal
std::vector<double> prop_phi = current_phi;
prop_phi[p] += rng.rnorm() * 0.05; 

// mcmc_sampler.cpp (Lines 37-40): Acceptance Evaluation
if (prop_ll < current_ll || std::log(rng.runif()) < (current_ll - prop_ll)) {
    current_phi = prop_phi;
    current_ll = prop_ll;
}
```

## 3. Parallelization Orchestrator
**File:** `src/fitting_procedures/bayesian_fitting_orchestrator.R`

### Intuition
Running an MCMC chain looping through 1,000 iterations for 3 architectures across 128 subjects serially would take weeks. The orchestrator delegates this task to independent CPU threads mapping across the $N=128$ subject factor list using the `doParallel` and `foreach` packages.

### Line-By-Line Code Mapping
```R
# bayesian_fitting_orchestrator.R (Lines 13-14)
cl <- makeCluster(detectCores() - 1)
registerDoParallel(cl)

# Lines 18-19: Initiate the parallel loop over subjects
results_list <- foreach(p = participants, .packages=c("Rcpp")) %dopar% {
    sourceCpp("src/fitting_procedures/mcmc_sampler.cpp")
    // Execute MCMC exclusively on the sliced participant dataframe
}
```
